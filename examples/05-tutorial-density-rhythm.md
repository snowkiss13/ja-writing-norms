# チュートリアルの解説文

HTTPリクエストへ指数バックオフを加える手順の一部です。
Beforeは内容を一段落に詰めているため、式、効果、例外の優先順位が見えにくくなっています。

## Before

HTTPリクエストが失敗した場合は、すぐに再実行するとサーバーに負荷がかかる可能性があるため、指数バックオフを使用して待機時間を増やします。
たとえば初回を500ミリ秒とし、失敗するたびに2倍にして最大8秒まで待機します。
複数のクライアントが同時に再試行するとアクセスが集中するため、ランダムな揺らぎも追加します。
429や一部の5xxは再試行の候補になりますが、GETのように結果が重複しない処理から適用し、更新を伴う処理では冪等性キーか同等の仕組みを確認する必要があります。

## After

失敗したリクエストを同じ間隔で繰り返すと、回復途中のサーバーへ同じ圧力をかけ続ける。
そこで、失敗するたび待機時間を増やす。

```js
const delayMs = Math.min(500 * 2 ** attempt, 8_000);
```

初回は500ミリ秒、次は1秒、その次は2秒になる。
待つ時間は増え、再試行の頻度は下がる。

ただし、すべてのクライアントが同じ式を使うと、次の試行時刻までそろってしまう。
`delayMs`へランダムな揺らぎを加え、集中する時刻をずらす。

ここで再試行の対象も絞る。
接続のタイムアウト、429、一部の5xxは候補になるが、同じ操作を繰り返してよいとは限らない。
まずGETのように結果を重複させない処理へ適用し、更新を伴う処理では冪等性キーか同等の仕組みを確認してから有効にする。

## 効いた規範

- `cognitive-rhythm-writing`の「段落の密度波形」と「文の拍」：機構、式、短い帰結、例外の順に密度を変え、長い説明を連続させなかった。
- `japanese-tech-writing`の「論証の厳密さ」：ステータスコードだけで再試行可否を決めず、操作の冪等性という条件を対応づけた。
